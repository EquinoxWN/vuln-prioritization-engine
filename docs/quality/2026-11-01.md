# Quality check against the 10 rules (2026-11-01 rule set, applied while building M1)

Run on 2026-11-14 on Windows 11 (Intel Core i7-13700H) with Python 3.14.5 in the repo's `.venv`.
Only the fixture files under `tests/fixtures/` were read by reports; no host was scanned. Mutations
were applied one at a time by a scratch script that restored each file right after its test run
(the script is not kept in the repository).

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | The only external calls are the optional downloads in `fetch.py`: `Client.request` passes a per-attempt timeout to `urlopen`, retries only `URLError`, `TimeoutError`, `ConnectionError`, 429 and 5xx with backoff `backoff * 2**(n-1)` and at most 5 retries, fails at once on other 4xx, caps the body at 32 MiB, and raises `FetchError` (exit 3). File reads raise `InputError` (exit 2) with the path. No bare or broad `except` in `src/` (ruff `BLE`, `E722`, `S110` enabled); the two places that fall back (unorderable fixed versions) return a defined value with a comment. Tests: `test_retries_transient_failures_with_backoff_then_succeeds`, `test_gives_up_after_bounded_attempts`, `test_client_errors_are_not_retried`. |
| 2 | Writes safe to retry | pass | Every write goes through `jsonio.atomic_write` (temp file in the same folder, `fsync`, `os.replace`, temp removed on failure): the JSON report, KEV, EPSS and each OSV record (`<id>.json`, so a re-run overwrites). Feeds are validated before the write. Tests: `test_json_report_rewrite_is_identical_apart_from_time`, `test_fetch_kev_validates_before_writing`, `test_fetch_osv_records_checks_ids_and_is_rerunnable`. |
| 3 | No race conditions | N/A | Single-threaded, no shared mutable state between calls; the CLI processes one command per run. |
| 4 | Don't trust the clock | pass | Report duration uses `time.perf_counter`; `generated_at` and the EPSS `fetched_at` are `datetime.now(UTC)` (asserted to end in `+00:00`); the report date for feed-age checks is the UTC date or `--as-of`. Retry backoff uses sleep durations, not timestamps. |
| 5 | Read before changing | pass | No environment variables are read by the code; `urllib` honours the standard `HTTPS_PROXY`/`NO_PROXY` variables, documented in the README. `packaging.version.Version`, `zipfile`, `gzip`, `urllib.request.urlopen(timeout=...)` exist in the installed versions (mypy strict passes). Every input format was checked against the real files: the OSV records and EPSS/KEV files are unmodified downloads (KEV trimmed, noted). Paths in the docs exist (`audit_repo.py` link check). |
| 6 | Never break compatibility | pass | First release. The JSON report has `tool` and `version` fields and new fields are added, not renamed (`upgrade_to` was added beside `fixed_versions`). Input readers accept documented formats and ignore unknown fields. |
| 7 | One source of truth | pass | Details come from the OSV record when one exists, named in `details_from`; scanners are the fallback (ADR 0003). Feeds are files with their date, version and source recorded in each report and in `tests/fixtures/SOURCES.md`; they are refreshed only by `vpe fetch`. Python >=3.11 in `pyproject.toml`, 3.12 in CI, 3.11+ in the README. |
| 8 | Small changes, no secrets, validate input | fixed | Secret scan: fixtures hold only public advisory data and hand-written SBOMs. Validated: file size (64 MiB, gzip output 256 MiB, OSV record 4 MiB, zip total and member caps), JSON decoding (UTF-8, nesting), vulnerability ids (pattern without `/`, `\` or `:`, so `vpe fetch osv` cannot write outside its folder), CVE ids, dates, probabilities, KEV `count`, CVSS vectors, purls, versions, entry counts, `--as-of`, `--max-feed-age`, `--timeout`, `--retries`, https-only URLs. The security pass found that package names and versions from a report could carry control characters (terminal escapes) into the text table; `make_package` now rejects them (`test_package_validation`). One runtime dependency (`packaging`) for PEP 440. |
| 9 | Tests that can actually fail | fixed | No tautologies, no skips. Failure and invalid-input paths are covered for each entry point. The offline matcher is checked against the OSV API's own answer, not against itself. First mutation run: 12/16 killed; the four survivors (alias merge through OSV, max EPSS, upgrade target, size limit) each got a test, and all 16/16 are killed. |
| 10 | Re-verify | pass | Results below; CI not run yet (repository not pushed). |

## Quality control (DMAIC)

| Phase | This repository |
|---|---|
| Define | Findings from several scanners and SBOMs overlap under different ids and lack exploitation signals. M1 counts when five input formats become one finding per vulnerability per package version with OSV details, EPSS and KEV ([RFC 0001](../rfc/0001-design.md)). |
| Measure | The tests above on an Intel Core i7-13700H with Windows 11: 163 passed; 59 findings with and without the scanner reports; offline matching equal to the OSV API on 10 of 10 packages. |
| Analyze | The first fixture run showed git commit hashes among the fixed versions (OSV `GIT` ranges) and the first two fixed versions of the whole record instead of the one for the installed line (log4j showed 2.3.1). The mutation run found four gaps: alias merging through the OSV database, the maximum EPSS choice, the upgrade target and the file-size limit were not pinned by a test. The security pass found that control characters in package names could reach the terminal. |
| Improve | Fixed versions come only from SEMVER and ECOSYSTEM ranges; a new `upgrade_to` field gives the lowest fixed version above the installed one (log4j-core 2.14.1 now shows 2.15.0 for CVE-2021-44228); four tests added (16 of 16 mutants killed); package fields with control characters are rejected. |
| Control | `.tmp/check.sh` and CI run lint, strict types, the tests (with exact counts and the OSV API oracle), the fixture report and `pip-audit` on every change; KEV `count` is checked so a truncated download fails; feed age is printed and checked; Dependabot PRs are paused and actions are SHA-pinned. |
